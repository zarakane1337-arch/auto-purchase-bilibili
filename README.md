## 第一步：登录

### 方式 A：一键浏览器登录（推荐）

点页面上的「**一键打开浏览器登录**」。

程序会用**独立的浏览器配置目录**（`data/browser-profile`，完全不碰你日常浏览器的数据）启动一个 Chrome/Edge 窗口，停在会员购首页。

你在里面正常登录（扫码、账号密码、短信都行），程序通过 **Chrome DevTools 协议**每秒查一次 Cookie —— 一旦出现 `SESSDATA` + `bili_jct` 就自动抓走、校验、存盘，然后关掉那个窗口。

- 自动查找 Chrome / Edge，优先 Chrome
- 全程不用复制粘贴，Cookie 只在本机回环（`127.0.0.1`）上传递
- 校验失败会**自动还原**原来的登录态，不会把已经登好的账号搞掉
- 超过 10 分钟没登录会自动放弃，点「取消」也可以随时中止
- 实现见 `core/browser_login.py`，CDP 用的 WebSocket 是 `core/ws.py` 里手写的（无第三方库）

### 方式 B：手动粘贴 Cookie

1. 浏览器登录 <https://www.bilibili.com/>
2. 打开 <https://show.bilibili.com/>，按 `F12` → **网络 / Network** → 刷新页面
3. 点任意一条 `show.bilibili.com` 的请求 → **标头 / Headers** → **请求标头 / Request Headers**
4. 复制整条 `Cookie:` 后面的内容
5. 粘进页面「账号」→「**或者手动粘贴 Cookie**」→「验证并登录」

只要 Cookie 里有 `SESSDATA` 和 `bili_jct` 就算成功：

- `SESSDATA` —— 登录态本体
- `bili_jct` —— CSRF token，下单接口必带

Cookie 只存在本地 `data/state.json`，不上传任何地方。

## 使用流程

1. **登录** —— 上面两种方式任选
2. **贴链接** —— 把会员购详情页链接粘进「场次票档」，点「解析」
   - 支持 `https://show.bilibili.com/platform/detail.html?id=1007085`
   - 支持纯数字 ID `1007085`
   - 解析完会列出所有场次（日期 + 票档数 + 售卖状态）和每个票档（价格 / 余票 / 限购）
3. **选场次和票档** —— 「开抢时间」会自动填成该票档的真实开售时间（服务器返回的 `saleStart`），可以手动改
4. **选实名** —— 点「从账号同步实名」拉取观演人列表，选中要买的那个人
5. **选模式 → 开始抢票** —— 页面上会实时滚动日志

抢到票后会显示订单号，并尽量给出支付链接。

## 三种模式

| 模式 | 用途 | 行为 |
| --- | --- | --- |
| **定时开抢** | 已知开售时间 | 对时 → 提前预热连接 → 到点并发下单 |
| **立刻开抢** | 已经在售 | 直接预热并并发下单 |
| **蹲票** | 回流票 / 捡漏 | 轮询库存，一旦有票立即下单，失败继续蹲 |

定时模式的「开抢时间」有两种填法：

- 选中票档后自动填入该票档的 `saleStart`（推荐，这就是真实开售时刻）
- 手动指定任意时间

时间基准是**服务器时间**，不是你的系统时钟 —— 本机快慢多少都会被对时抵消掉。

## 参数说明

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 并发线程 | `2` | 同时下单的线程数（1–5）。越大越容易撞风控，一般 2–3 够用 |
| 重试间隔 ms | `120` | 单次失败后隔多久再试 |
| 预热提前 ms | `1500` | 开抢前多久建立 TLS 连接 |
| 最长抢票 秒 | `300` | 整个任务的总窗口，超时放弃 |
| 单轮开抢 秒 | `300 / 120 / 60` | 一轮下单最多打多久（定时 / 立刻 / 蹲票各自默认）。蹲票一轮没抢到要能回到轮询，所以单独限时 |
| 蹲票轮询 ms | `800` | 蹲票模式查库存的间隔 |
| 单订单锁 | 开 | 并发线程里只允许一个真正发出 `createV2`，其余在途请求立刻放弃，避免限购 > 1 时下出两张票 |

## 它为什么快

抢票的本质是**在正确的时刻把请求发出去**，而不是「点得快」。四件事决定了成败：

**1. 对时（消除本机时钟误差）**
用 HTTP `Date` 头做整秒边界探测：连续发若干请求，看服务器返回的秒数什么时候跳变，用跳变点反推真实时间偏移。实测能把误差压到 RTT/2 以内（约 ±70 ms）。开抢按服务器时间算。

**2. 预热（省掉握手）**
开抢前 `1500 ms` 先把 N 条 TLS 连接建好放进池子（`HostClient.prewarm`）。开抢瞬间直接复用，省掉 TCP + TLS 的 2–3 个 RTT。

**3. 精确等待（不靠 `sleep`）**
最后一段不用 `sleep`：

```
剩余 > 20s  → 粗睡
剩余 > 1s   → 睡 (remain - 0.6)
剩余 > 0.12s→ 睡 10ms 粒度
最后一段    → 纯自旋
```

实测开抢时刻与目标偏差 **0 ms**。

**4. 并发 + 单订单锁**
多线程同时 `prepare → createV2`，谁先成功就停谁；同时用 `single_order` 锁保证并发下**不会重复成单**。

## 下单链路

```
GET  /api/ticket/project/getV2?version=134&id=<项目>&project_id=<项目>
     └─ 项目详情：场次 screen_list[].ticket_list[]，票档带 price / num / static_limit

GET  /api/ticket/buyer/list?project_id=<项目>
     └─ 观演人列表（personal_id 是打码的，如 441************010）

POST /api/ticket/order/prepare?project_id=<项目>
     └─ 拿 token

POST /api/ticket/order/createV2?project_id=&screen_id=&sku_id=
     └─ body: buyer_info / deliver_info / token / pay_money / again / timestamp
     └─ 订单

POST /api/ticket/order/pay?project_id=<项目>
     └─ 支付参数 → 拼出支付链接
```

几个实测踩过的坑，已写进代码：

- 列表接口必须带 `platform=web`、`area=<数字>`、`p_type=0`，否则返回 `param missing error`
- 票档在 `screen_list[].ticket_list[]` 里，顶层 `sku_list` 是空的
- 未登录时 `errno` 是 `2`（不是 `-101`），要单独归到 auth 类
- 请求体必须是 UTF-8 字节 —— `http.client` 默认按 latin-1 编码 str，中文姓名会直接 `UnicodeEncodeError`

## HTTP 接口

后端是手写的 `http.server.ThreadingHTTPServer`，前端就是它的一个客户端。想二次开发可以直接调：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/health` | 服务状态、登录态、账号信息 |
| `GET` | `/api/session` | 当前会话（是否登录、用户信息） |
| `POST` | `/api/login/cookie` | 粘贴 Cookie 登录 |
| `POST` | `/api/login/browser` | 启动一键浏览器登录 |
| `GET` | `/api/login/browser/status` | 一键登录进度（轮询） |
| `POST` | `/api/login/browser/cancel` | 取消一键登录 |
| `POST` | `/api/logout` | 退出登录 |
| `POST` | `/api/parse` | 解析会员购链接 |
| `GET` | `/api/buyers` | 拉取观演人列表 |
| `GET` | `/api/ntp` | 对时（返回偏移与 RTT） |
| `POST` | `/api/task` | 开始抢票任务 |
| `POST` | `/api/task/stop` | 停止任务 |
| `GET` | `/api/tasks` | 任务列表与状态 |
| `GET` | `/api/events` | SSE 实时日志流 |

## 常见问题

| 提示 / 现象 | 原因与处理 |
| --- | --- |
| `账号未登录` / `请先登录` | Cookie 过期了，重新登录 |
| `该实名信息不在账号观演人列表中` | 填的姓名+身份证不是账号里已添加的观演人。先在 bilibili 里添加观演人，或点「从账号同步实名」 |
| `超过限购` / `已达上限` | 这个票档你已经买过了 |
| `已结束` / `不存在` | 场次下架，或者链接不对 |
| `接口繁忙` 一直重试 | 风控限流。降低并发线程数、加大重试间隔 |
| 抢到但没付款 | 页面会给出支付链接。会员购订单通常 **15 分钟内**要付款，超时自动取消 |
| 一键登录弹不出浏览器 | 没装 Chrome/Edge，或者被安全软件拦了。改用「手动粘贴 Cookie」 |
| 页面打不开 | 端口被占用。看命令行提示，它会告诉你已有实例的地址 |
| 双击 `run.bat` 闪退 | 大概率是没装 Python。命令行跑 `python --version` 确认，或装 Python 时勾上「Add to PATH」 |

## 注意

- **只监听 `127.0.0.1`**，默认不对外暴露。改成 `0.0.0.0` 等于把带登录态的接口开放给整个局域网，别这么干。
- **Cookie 等同账号密码**。`data/state.json` 里是明文的，别提交到 Git、别发给别人（`.gitignore` 已经挡掉了）。
- **`data/browser-profile` 是一整个浏览器配置**，里面同样有登录态。分享项目时把这个目录排除掉。
- 抢票结果以 bilibili 服务端返回为准。本工具只负责**把请求在正确的时间发出去**，抢不抢得到还取决于库存、风控和运气。
